# Definition of Ready and Done

## Definition of Ready

A work item is ready only when it has:

- problem statement;
- target user or stakeholder;
- current and desired behavior;
- measurable outcome;
- acceptance criteria;
- constraints and non-goals;
- affected systems;
- data classification;
- dependencies;
- risk owner;
- decision authority;
- unresolved questions classified as blocking or non-blocking.

## Definition of Done

- all approved acceptance criteria have evidence;
- TDD evidence exists for changed behavior;
- required tests pass;
- required policies pass;
- no unresolved critical/high findings;
- authorization and tenant isolation are verified;
- migrations and RLS are verified when applicable;
- documentation and ADRs are current;
- observability and support ownership are defined;
- rollback or disablement path is documented;
- release evidence is generated and approved;
- technical debt is explicitly recorded rather than hidden.
